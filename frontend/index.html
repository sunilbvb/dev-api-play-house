📖 Documentation & Readme Overview

Open-Source & Zero-Dependency

👾 About Dev API Play House

Dev API Play House is an open-source, zero-dependency API management suite, interactive developer playground, and gamified lifecycle DAG engine. It bridges the gap between static, disconnected API runners (like Postman or Insomnia) and real-world system lifecycle dependencies.

Instead of running isolated requests, Dev API Play House autonomously discovers authentication prerequisites, token extraction rules, and multi-step state cycles, mapping your endpoints into an interactive, gamified Game House dungeon featuring dynamic rooms, vitals HUD, and Raid Boss battles.

🛡️ 100% Python Standard Library — Zero pip packages, zero npm builds, 0 external CVE vulnerabilities.
⚡ Sub-Millisecond Engine — Embedded SQLite3 and pure socket-level urllib HTTP client.
🗺️ Autonomous DAG Dependency Engine — Automatically sequences login, player setup, actions, and scoring.
🧪 Built-in QA Advisor & Auto-Documentation — 1-click Markdown specs and 6–8 dimensional test matrices.

🚀 Server Setup & Installation Guide

Zero Pip Dependencies

Quickstart: Run Interactive Web Studio

python3 app.py

Default address: http://localhost:8080. Automatically initializes local SQLite database and pre-seeds sample Arcade Game Quest.

Customize listening port and host via environment variables:

PORT=9090 python3 app.py

Headless CI / CD Pipeline Runner

python3 app.py --cli --min-hp 70
Flag Default Description
--cli False Runs in headless automated terminal mode without launching the web server.
--min-hp <N> 80 Minimum required House HP percentage (0–100). Exits with code 1 if threshold is not met.
--col <ID/Name> 1 Specific Collection ID or name to execute.
--chaos <level> off Simulate Boss Enrage mode during CI run (light, medium, insane).
--out <file> None Export execution summary and time-travel tape to a JSON file.

🏰 Architecture & Autonomous DAG Solver

Topological Dependency Sequencing

The Game API House Paradigm

Traditional API tools treat endpoints as flat, isolated lists. Dev API Play House models API systems as a living gamified dungeon:

🛡️

1. Gates & Auth

Login, OAuth, sessions, JWT token issuing endpoints. Evaluated first to harvest credentials.

⚔️

2. Armory & Player

User profile, character inventory, balance checks, setup endpoints.

💥

3. Coliseum & Action

Core gameplay actions, state mutations, match rounds, transactional APIs.

🏆

4. Vault & Leaderboard

Score submissions, leaderboards, stats, logout, and completion checks.

Dynamic Variable Extraction & Chaining

Any API can declare extraction rules in its configuration. Chained variables are passed down the DAG in runtime memory:

Source Type Target Property Example Rule
body_json Dot-notation path token or data.user.id
header Header key Set-Cookie or Authorization
status Status code last_status
regex Regular expression bearer\s+([a-zA-Z0-9_\-\.]+)

Supported Dynamic Macro Variables:

  • {{$timestamp}}: Current Unix epoch timestamp in seconds.
  • {{$isoTimestamp}}: ISO 8601 UTC timestamp (e.g. 2026-10-04T00:00:00Z).
  • {{$guid}} / {{$uuid}}: Cryptographically random UUID v4.
  • {{$randomInt}}: Random integer between 100 and 999999.

🧪 QA Playbook & Multi-Way Test Advisor

Automated Inspection & Fuzzing

Multi-Way Test Strategy Advisor

Instead of guessing how to test an API, the Test Advisor inspects endpoint methods, parameters, and bodies to generate 6-8 distinct test ways:

Way Dimension What It Tests Expected Outcome
1. Happy Path Functional Baseline Exact configured headers and payload HTTP 2xx Success
2. Empty Body Payload Boundary Sends empty body {} HTTP 400 Bad Request
3. Auth Stripped Security Verification Removes Authorization/API-Key headers HTTP 401 Unauthorized
4. Bad Field Types Type Safety Fuzzing Flips numbers to strings, objects to booleans HTTP 422 / 400 Validation Error
5. Method Tampering HTTP Protocol Compliance Swaps POST/GET with incompatible method HTTP 405 Method Not Allowed
6. Latency SLA Performance Verification Measures wall-clock elapsed time < 500 ms SLA response

Automated Documentation Generator

Inspects the live request model, extracts URL query params, detects path variables (e.g. {id}), infers JSON body schemas with field types, and compiles ready-to-publish GitHub Markdown docs including QA checklists with a single click.

Boss Enrage Mode & Chaos Monkey

Toggle ⚔️ Boss Enrage Mode to stress-test your frontend and API clients against real-world chaos conditions:

  • Latency Spikes: Random delays between 200ms and 1500ms injected.
  • HTTP 429 Rate Limits: Simulates server throttling under load.
  • HTTP 500 Crashes: Simulates unexpected backend downstream outages.
  • Token Corruption: Tampering authorization headers to verify retry logic.

🤝 Contributing Guidelines

Open-Source Community

Welcome Contributors!

Contributions are warmly welcomed! Whether you are fixing bugs, improving documentation, adding new import formats, or creating new game themes, please follow our architectural standards:

🛡️ Zero 3rd-Party Dependencies: Backend code must rely 100% on the Python Standard Library. Never introduce pip packages into backend/.
📦 Clean Modular Subpackages: Group backend domain logic in backend/<domain>/ with __init__.py.
🖥️ Vanilla ES6 Frontend: Group JavaScript into clean single-responsibility submodules in frontend/js/modules/<domain>/.
📖 Living Documentation Synchronization: Whenever modules or endpoints are added or modified, update README.md, ARCHITECTURE.md, FAQ.md, and docs/API.md.

Pull Request Workflow

  1. Fork the repository on GitHub.
  2. Create a feature branch: git checkout -b feat/amazing-feature.
  3. Verify all modules import cleanly without third-party packages: python3 app.py --cli --min-hp 70.
  4. Commit your changes with conventional commit prefixes: git commit -m "feat: add GraphQL live explorer".
  5. Push to the branch and open a Pull Request.
